Detailed Description

Locates the sibling executable and starts it as this process's replacement.

The two shells never run at the same time. Both own the same hardware exclusively — the Basler camera (Pylon grants exclusive access), the MC PLC socket and the vision-output listen port — so switching is a hand-off, not a launch: stop the work, release the devices, start the sibling, exit. Both shells therefore take the same single-instance key (kInstanceKey), which is what makes "one app at a time" a fact rather than an operating instruction.

That creates one hazard worth naming, because its failure mode is silence: the outgoing process must release the lock before the incoming one takes it, and the incoming one starts first. A shell launched for a hand-off therefore waits (kHandoffAcquireTimeoutMs) instead of giving up immediately — see wasStartedForHandoff().

Note
The sibling is found via QCoreApplication::applicationDirPath() plus a fixed filename. That is why both executables must ship in one folder, which the Phase 6 install image already guarantees (docs/product/install_image.md).

◆ kHandoffAcquireTimeoutMs

int vc::shell::ShellHandoff::kHandoffAcquireTimeoutMs = 15000
staticconstexpr

How long a hand-off launch waits for the outgoing shell to release the lock.

Generous on purpose. The outgoing shell still has to stop device runners and let their threads finish, and the cost of waiting too long is a few seconds of splash; the cost of waiting too little is an application that appears not to start at all.
